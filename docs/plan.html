Working name: inkloop

A local-first review loop for agent-written HTML

Goal: a CLI + browser UI where an agent writes an HTML artifact, a human annotates specific elements or text ranges, feedback queues up, and the agent long-polls for it and iterates — no accounts, no cloud dependency in the core loop. Closest prior art is lavish-axi, which already does this well. This document is the prior-art study, scope call, naming check, and stack proposal — annotate anything you want changed before implementation starts.

2. Core loop, as it will work

Non-negotiable for v1 regardless of what else gets deferred.

sequenceDiagram
    participant Agent
    participant Server as Local server (loopback)
    participant Browser as Browser UI
    Agent->>Server: write artifact.html, open session
    Server->>Browser: launch / resume tab
    Browser->>Browser: human selects element or text range, writes comment
    Browser->>Server: queue feedback
    Agent->>Server: poll (long-poll, blocks)
    Server-->>Agent: feedback batch (once queued)
    Agent->>Agent: revise artifact.html
    Agent->>Server: poll again with --agent-reply
    Server->>Browser: live reload, preserve scroll + unsent draft
    Browser-->>Agent: session continues or ends

3. v1 scope recommendation

Layout-issue inbox and Mermaid editing are lavish-axi's standout differentiators — and also its most complex pieces. Decided: ship the core loop alone in v1; both differentiators are noted down for v2.

Core loop

v1 — in

Open → annotate element/text range → queue → long-poll → agent revises → live reload with state preservation. This is the entire non-negotiable spec.

Effort: moderate. Differentiation: table-stakes, but doing it with a smaller install footprint than lavish-axi is itself a real pitch.

Layout/QA issue inbox

v2

Passive render-audit + stateful issue lifecycle (open/queued/resolved/returned) is genuinely hard to get right without false positives, and lavish-axi already does it well.

Effort: high (viewport matrix, fingerprinting, false-negative guards). Revisit once core loop is proven and there's a concrete complaint it would fix.

Mermaid diagram editing

v2

Embedding Excalidraw, scene autosave, staleness detection on source change — a large surface for a feature most sessions won't touch.

Effort: high (third-party whiteboard integration). Niche relative to the core review loop.

Adopt one idea from sidenote-cli regardless of scope: drift detection — refuse (or flag) resolving a comment anchored to a text range whose source has since changed, rather than silently editing the wrong thing.

5. Proposed tech stack

Biased toward minimal install weight — this tool gets installed ambiently by agents via npx, so every dependency is a tax on every session. Ships as a single npm package (CLI, server, and the injected SDK all bundled together) rather than split packages — one install surface, one version to reason about.

CLI / local server

Node.js + TypeScript, built on the built-in node:http module rather than Express — matches lavish-axi's runtime choice (broadest npx compatibility across agent harnesses) while cutting the one framework dependency it carries.

Injected browser SDK

Vanilla TypeScript compiled to a single IIFE, zero runtime dependencies. No UI framework — keeps the injected footprint tiny and guarantees it can never visually or behaviorally clash with whatever the artifact itself uses.

Long-poll transport

Plain HTTP long-poll, bounded to ~30s per request with the CLI re-issuing automatically. No WebSocket dependency — each poll call is a discrete agent-process invocation anyway, so a persistent socket buys nothing.

Session / state persistence

Flat JSON files under ~/.inkloop/<hash-of-absolute-path>/. Single local user, low write concurrency — SQLite would be a dependency with no payoff at this scale. Revisit only if the drift-detection feature needs indexed lookups.
